# Política de segurança

## Versões suportadas

A versão publicada na branch padrão recebe correções de segurança.

## Relato de vulnerabilidades

Evite publicar dados sensíveis em issues. Envie um relato privado pelo recurso **Security Advisories** do repositório, quando disponível, contendo impacto, passos para reprodução e sugestão de correção.

## Controles adotados

- Política CSP com origens explícitas.
- Ausência de segredos no frontend.
- Permissões mínimas para GitHub Actions.
- CodeQL para análise estática.
- Revisão por pull request recomendada para mudanças na branch padrão.
- Autenticação em dois fatores recomendada para colaboradores.

## Responsabilidade do administrador

O responsável pelo repositório deve revisar alertas do GitHub, manter a autenticação em dois fatores e remover acessos que deixarem de ser necessários.
